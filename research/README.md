# Lonelybot Research Bench

Experimental harness for evaluating heuristic, MCTS, oracle and belief-based Klondike agents.

This branch is intentionally isolated from `main` while the research workflow is validated.

## Dynamic imperfect-information architecture

Phase 0.2 showed that the legacy static `PartialState` is not sufficient for mid-game research because it does not preserve the complete public state/history. The Phase 1 core therefore uses two strictly separated objects:

- `ResearchGame.true_state`: evaluator-only hidden truth.
- `ResearchGame.belief`: the agent-visible `BeliefState`.

`BeliefState` constrains the 52 **initial deal slots** rather than rebuilding a mid-game position from scratch. Only legitimately observed cards are bound to those slots. A particle is generated by:

1. randomly filling the still-unknown initial slots;
2. creating a complete initial Klondike deal;
3. replaying the complete public `StandardMove` history;
4. rejecting the particle if it does not reconstruct the exact current public snapshot.

The public snapshot preserves visible tableau cards, hidden-card counts, all four foundations, stock/waste cursor and current waste top. Previously observed stock cards remain constrained through stable initial-slot IDs even after stock removals and cycles.

### Validation gate

`lonecli/src/bin/belief_validate.rs` replays Oracle solutions as real public StandardMoves and samples particles after every action. Phase 1 particle search must not start until every sampled particle reproduces the same public snapshot across dynamic play.
